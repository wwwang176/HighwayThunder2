# Highway Thunder 2 — 設計文件

日期：2026-10-31

## 1. 意圖

一款在瀏覽器中執行的 3D 高速公路賽車遊戲。玩家駕車在單向 4 線道的直線高速公路上，穿越由一般車輛、貨車、貨櫃車組成的車流，以最短時間抵達 10 公里外的終點。

**核心體驗（使用者原話）：「精準控制來回穿梭車陣」。**
所有設計取捨都以此為準：操控要反應快、可預期；車流要密到「必須穿梭」才跑得快；NPC 的行為要能被玩家預判。

## 2. 目標 / 非目標 / 反目標

### 目標
- 玩家能在高速（200 km/h 以上）下做出精準的小幅度換線，穿過車與車之間的縫隙。
- 路上車輛會自主跟車、變換車道、閃避，車流有生命感。
- 有真實的物理碰撞：車有重量，撞擊會彈開、打轉；貨櫃車的拖車會甩動。
- 單一關卡跑完 10 公里，計時並顯示成績。

### 非目標（這一版不做）
- 彎道、坡道、地形起伏（使用者決定：一路直線）
- 觸控 / 手把操作（使用者決定：先鍵盤）
- 多關卡、多路線、難度選擇（使用者決定：單一關卡 10 km）
- 對向車道、匝道、交流道
- 車內視角（使用者決定：第三人稱）
- 多人連線、排行榜伺服器
- 改裝、車輛選擇、劇情

### 反目標（就算「能動」也算失敗）
- 操控像在跟車子搏鬥：高速一按方向就打滑、飛出車道、難以修正。
- 車流稀疏到玩家只要待在空車道就能一路全速衝到底。
- NPC 突然瞬間切入、毫無預兆，讓碰撞感覺是運氣而非技術。
- 鏡頭劇烈搖晃，讓玩家無法判斷與前車的距離。
- 掉幀 / 卡頓（高速穿梭時任何卡頓都會直接毀掉手感）。

## 3. 使用者已決定的事項

| 項目 | 決定 |
|---|---|
| 視角 | 第三人稱追尾鏡頭 |
| 撞車 / 卡住處理 | 按 **R** 重置位置（回到車道上、恢復行駛） |
| 道路 | 一路直線 |
| 操作 | 鍵盤 |
| 關卡 | 單一關卡，長度 10 km |
| 車種 | 一般車輛、貨車、貨櫃車 |

## 4. 設計

### 4.1 技術棧（我的決定）
- **Three.js**：3D 渲染
- **Rapier**（`@dimforge/rapier3d-compat`）：物理引擎
- **Vite + TypeScript**：開發與建置
- 純前端，無後端。最佳成績存在 `localStorage`。
- 目標效能：一般桌機 / 筆電瀏覽器（Chrome / Edge）穩定 60 FPS。

### 4.2 道路
- 單向 4 線道，車道寬 3.75 m；兩側有路肩與護欄（護欄為物理碰撞體，玩家不會掉出路外）。
- 全長 10 km，起點有起跑線、終點有明顯的終點門。
- 道路以「路段（chunk）」方式生成與回收，只保留玩家前後一段距離內的幾何，避免一次建立 10 km 的物件。
- 路面有車道線（虛線）以強化速度感與車道判讀。
- 路邊需有足夠的參照物（燈桿、標誌、距離牌等）來提供速度感；具體內容由實作者決定。
- 畫面上顯示剩餘距離。

### 4.3 玩家車操控
- 使用自訂的街機車輛模型：Rapier 動態剛體（只允許繞垂直軸旋轉，不會翻車），由程式直接控制縱向加減速、側向抓地與偏航角速度；碰撞後有短暫的「失控」時間，期間降低抓地力與操控，讓物理引擎的撞擊效果呈現出來。（原本考慮用 Rapier 的 raycast 車輛控制器，改用自訂模型是因為「精準」的手感更容易調整。）
- **調校方向：街機手感**
  - 高側向抓地力，一般駕駛下不會打滑。
  - 轉向反應快，放開方向鍵後車身自動回正。
  - **轉向角隨速度遞減**：低速轉得大，高速轉得細，讓高速下也能做精準的小幅換線。
  - 最高速度約 300 km/h（我的決定，可調）。
- 鍵盤配置（我的決定）：
  - `W` / `↑` 油門、`S` / `↓` 煞車（停下後倒車）
  - `A` `D` / `←` `→` 轉向
  - `R` 重置
  - `Esc` 暫停
- **R 重置**（我的決定，用來防止被拿來作弊）：
  - 把玩家車放回最近的車道中央、車頭朝前、清除旋轉與角速度。
  - 重置點**只能在目前位置或後方，永遠不會往前移**。如果該處有 NPC 或事故車，就往後退到安全的位置，所以不能用 R 瞬移越過車陣。
  - 重置後給一個固定的低起步速度（約 60 km/h，可調），遠低於比賽中的速度，所以不會變成加速捷徑。
  - 只有在 GO 之後才能使用，並有短暫冷卻時間（約 3 秒），避免連按。
- 開發期提供即時參數調整面板（例如 lil-gui），用來調校手感；正式版可隱藏。

### 4.4 交通車輛（NPC）

**車種**
| 車種 | 特性 |
|---|---|
| 一般車輛 | 輕、速度較快、換道較頻繁 |
| 貨車 | 較重、較慢、換道較少且較慢 |
| 貨櫃車 | 車頭 + 拖車，以關節連接；最重最慢、幾乎只在外側車道、換道最慢 |

**行為模型**
- **跟車**：IDM（Intelligent Driver Model）。依前車距離與速度差自然加減速。
- **換道**：MOBIL 模型。評估換道後是否較有利、是否會讓後車急煞，才決定換道。
- **換道預告**：換道前先打方向燈一段時間，再以平滑的曲線移動到隔壁車道，**不得瞬間切入**。這是「玩家能預判」的關鍵。
- **對玩家的反應**：玩家高速從後方逼近時，NPC 會把玩家視為一般車輛納入 MOBIL 計算，偶爾讓道。
- 每台 NPC 有隨機的期望速度與駕駛性格（保守 / 積極），讓車流不至於整齊劃一。

**物理模式切換與事故（使用者決定）**
- 平時 NPC 由 AI 直接控制位置（實作上是「每一步由 AI 設定速度的動態剛體」，而不是 kinematic 剛體，因為 kinematic 的質量無限大，玩家撞上去會像撞牆，無法產生撞飛的效果）。AI 狀態是權威來源，物理只負責碰撞。
- **任何碰撞（包括輕微擦碰）**，不論來自玩家或其他失控車輛，都會讓 NPC 切換為 **動態剛體**，交給物理引擎處理彈開、打轉。**允許連環車禍**，這是使用者明確接受的。
- 失控後的 NPC 會**煞車，在原地停下**（例如提高阻尼或摩擦，讓它在短距離內停住，不會一路滑行）。之後不再恢復 AI 駕駛。
- 事故車輛**經過一段時間後消失**（時間長短由實作者調整）。
- **其他 NPC 必須能看到事故車輛並煞車或繞開。** 事故車可能斜停、橫跨兩條車道，所以 AI 的障礙物偵測不能只看「同車道正前方那台車」，而要依照實際的橫向佔用範圍判斷哪些車道被擋住。
- 效能保護（我的決定）：同時存在的事故車數量設上限。超過上限時，先移除最舊、且不在玩家前方視野內的事故車。

**貨櫃車拖車（我的決定）**
- 未發生事故時，拖車以運動學方式跟隨車頭（換道時呈現自然的拖曳角度）。
- 發生事故後，車頭與拖車都變成動態剛體，以關節連接，拖車可以甩動或折刀。

**行駛方向（我的決定）**
- 靠右行駛。「外側車道」指最右側的車道；貨櫃車與貨車偏好行駛於右側車道。

**生成與回收**
- 只在玩家前後一段範圍內（約數百公尺）維持 NPC；超出範圍的回收，前方持續補車。
- 車流密度需調整到「必須穿梭才能跑得快」，但仍存在技術上可通過的縫隙。
- 起跑時玩家前方要有車流，不能出現開局一段完全無車的空路。
- **起跑處理（我的決定）**：倒數期間玩家停在起跑線上，所以開局時**只在玩家前方生成車流**，前方最近的車也要保持一段安全距離。玩家後方的車流等玩家起步、速度提上來之後才開始生成，避免玩家在起跑線上被後方來車追撞。

### 4.5 碰撞與懲罰
- 撞擊由物理引擎自然處理：玩家車會減速、被彈開、可能打轉。
- 沒有血量、沒有 Game Over。懲罰就是損失的時間。
- 卡住、翻車、轉向時，玩家按 R 重置。
- 撞擊需有回饋：碰撞音效、短暫輕微的鏡頭震動（輕微，不能影響判斷）。

### 4.6 險過（Near-miss）
- 玩家以高速貼近 NPC 側面擦身而過、但沒有碰撞時，畫面顯示「險過」提示。
- 回饋形式這一版只做提示與計數（我的決定），不給加速，也不影響成績；成績只看時間。是否加入獎勵機制留待試玩後決定。

### 4.7 鏡頭
- 第三人稱追尾，跟隨平滑但不拖泥帶水（高速換線時鏡頭不能延遲到讓玩家看不清車頭位置）。
- 速度越快 FOV 越大，強化速度感。
- 鏡頭不隨車身側傾或打滑劇烈旋轉；撞擊時才有輕微震動。

### 4.8 遊戲流程與畫面
1. **標題畫面**：遊戲名稱、操作說明、最佳成績、「開始」。
2. **倒數**：3、2、1、GO，倒數期間玩家車不能前進。
3. **比賽中 HUD**：時速（km/h）、經過時間、剩餘距離、險過次數。
4. **抵達終點**：顯示完成時間、是否刷新最佳成績、險過次數，可「再玩一次」。
5. **暫停**：Esc 暫停 / 繼續 / 回標題。

### 4.9 介面語言
- 介面文字使用繁體中文（我的決定）。

### 4.10 視覺與音效
- 初版車輛以程式產生的 low-poly 幾何（方塊組合）呈現，三種車種在輪廓與大小上要一眼可辨；後續可換成 CC0 glTF 模型。
- 白天、晴天，基本光影即可。
- 音效（我的決定，初版用 Web Audio 合成或 CC0 素材）：引擎聲隨轉速變化、碰撞聲、險過提示音。

## 5. 限制
- 純瀏覽器執行，不需安裝；以鍵盤操作。
- 物理在高速下要穩定：時速 300 km/h 約每秒 83 m，必須用固定時間步長與子步進，玩家車啟用 CCD，避免穿透。
- 遊戲邏輯使用固定時間步長，不受顯示器更新率影響。

## 6. 留給實作者決定的事
- 專案目錄結構與模組切分。
- 所有手感與 AI 參數的具體數值（抓地力、轉向曲線、IDM / MOBIL 參數、車流密度、生成距離）。以試玩調校為準。
- 路邊參照物的種類與擺放。
- low-poly 車輛的具體造型與配色。
- 測試方式：純邏輯部分（IDM、MOBIL、換道判斷、計時、生成 / 回收）應有單元測試；手感部分靠試玩。

## 7. 建議的開發順序
1. **MVP**：直線道路 + 護欄、玩家車物理與操控、追尾鏡頭、計時、終點、R 重置
2. **交通**：一般車 + IDM 跟車 + MOBIL 換道 + 方向燈 + 生成回收
3. **車種**：貨車、貨櫃車（拖車關節）、碰撞時 kinematic → dynamic 切換
4. **遊戲流程**：標題、倒數、HUD、結算、暫停、最佳成績
5. **手感與回饋**：轉向曲線調校、險過、FOV、音效、撞擊回饋
