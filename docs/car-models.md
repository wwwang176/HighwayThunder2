# 車輛模型製作流程

做肌肉車和超跑（2026-11）時摸索出來、確定可行的做法。下一台車照這份走，最後的「新車清單」是完整步驟。
相關：`docs/ai-car-tuning.md`（新車進遊戲後量車、訓練 AI）。

## 0. 先記住的結論

- **不要用程式手刻車身。** 肌肉車先用 Blender 腳本從零放樣，修了十幾輪仍越改越糟。改成「AI 生成車身＋腳本後處理」後，一次就比手刻好。
- **車身交給 Tripo3D，細節交給後處理腳本。** 輪子、燈具、玻璃、塗裝、對稱、尺寸都在腳本裡做，結果可重現，可以一直改。
- **判斷什麼都要看圖。** 每一步都渲染出來看，不要只看數字。檢查玻璃時，把玻璃材質換成藍色渲染最清楚。

## 1. 授權

- 送給 Tripo 的只能是**我們自己的圖**（`docs/art/<car>/` 的概念圖）。
- 別人的模型（例如 Sketchfab 下載的）只能拿來參考比例，**不能**送進 Tripo，不能放進 repo，不能在程式、註解、commit 裡提到。
- Tripo 免費方案的產出是 CC BY 4.0，依其條款權利歸 Tripo；**付費方案**才是權利歸我們、可商用、不用署名。

## 2. 概念圖

- 用 grok 產生三張：前斜角 `front34.jpg`、側面 `side.jpg`（車頭朝左）、後斜角 `rear34.jpg`。提示詞存在 `grok-prompt.txt`。
- 風格：low-poly、單色車漆加條紋、素色灰背景、整台車入鏡。

## 3. 用 Tripo 生成

工具：`tools/models/tripo.py`（只用 Python 標準庫）。

```sh
python tools/models/tripo.py balance
python tools/models/tripo.py multiview docs/art/<car>/front34.jpg docs/art/<car>/side.jpg docs/art/<car>/rear34.jpg -
python tools/models/tripo.py wait <task_id> <scratch 資料夾>
```

- **金鑰**：環境變數 `TRIPO_API_KEY`，Windows 用 `setx` 設定，腳本會從登錄檔讀。這把是 `api.tripo3d.ai` 的 v2 金鑰，新的 v3 網址（`openapi.tripo3d.com`）不收。
- **參數**（寫在腳本裡）：`v3.1-20260211`、`smart_low_poly`、`face_limit 5000`（實際約 5800 面）、`texture` 開、`pbr` 關。每次 40 點。
- **多視角比單張好**：只給 `front34` 時車頭很好，但車尾靠猜，尾燈陽春。三張一起給，順序是前、左、後（右留空），車尾就對了。斜角圖放在「前」「後」的位置也能用。
- 挑一個結果，把 `model.glb` 存成 `tools/models/src/<car>-tripo.glb`（進 repo）。

## 4. 後處理腳本

共用的步驟都在 `tools/models/carkit.py`，輪子在 `tools/models/wheels.py`。每台車一個小檔（`muscle_car.py`、`supercar.py`）：用 `kit.Car(...)` 寫出這台車的設定（輪胎位置、尺寸、塗裝、輪胎規格、輪框、燈具、自己的修補），再呼叫 `kit.run(CAR)`。各參數的意思寫在 `Car` 的說明裡。

```sh
blender -b --factory-startup -P tools/models/<car>.py -- --out public/models/<car>.glb --preview <scratch 資料夾>
```

不加 `--out` 就直接寫進遊戲（`public/models/`）。碰撞外形是手寫的，腳本只讀不寫（見 11-1）。改了 `carkit.py` 後，要重建其他車比對輸出有沒有變（`cmp` 新舊 GLB、塗裝 JPEG）。

腳本依序做這些事，每一步都有做法和踩過的坑：

1. **匯入**：`import_scene.gltf(merge_vertices=True)`。不加的話，glTF 會在 UV 接縫把頂點拆開，整台車會變成幾百個碎塊。
2. **轉向和尺寸**：Tripo 輸出約 1 m 長，車頭朝 +x。先轉成車頭朝 +y、輪胎底在 z=0、原點在前後軸中點。**先在固定尺寸下處理**（肌肉車用 4.25 m 長），最後再整體等比放大到目標寬度。這樣所有量好的常數都不用跟著尺寸改。
3. **左右對稱**：`bmesh.ops.symmetrize(direction="X")`，右半鏡射到左半，中線自動焊接。
4. **拆掉輪胎**：在原始模型上量出四個輪胎的圓柱範圍（軸心、半徑、內外側），把頂點全在範圍內的面刪掉。接著：
   - 刪掉輪胎接地處留下的小碎塊（頂點少於 20 的獨立塊）。
   - 用 `holes_fill` 補輪拱上的洞，新面的 UV 取自旁邊的頂點。
5. **焊掉穿插**（`unfold`）：生成的表面偶爾會摺到自己身上。把每對互相穿插的面裡最近的兩個頂點焊在中點，重複到沒有穿插為止。
6. **修局部造型**（肌肉車是下巴的缺口，用 `build_apron`）：沿著保險桿輪廓做一塊實心補塊，用 exact boolean（`use_hole_tolerant`）合併。
   - **補塊的貼圖要「每個面一個 texel」**，取自離它最近的車身面的顏色。如果每個頂點各取 UV，貼圖會橫跨不同的 UV 島，變成一團花紋。
7. **燈具**：從貼圖找位置。在車頭、車尾打一格一格的射線，每條射線命中處讀貼圖顏色：
   - 大燈：白色命中點分成左右各兩群，每群做一顆圓燈（面積換算半徑）。
   - 尾燈：取「紅色比例高的連續列」裡最長的一段當燈條，不要用百分位數，否則會把上下零星的紅線算進去。做成貼著車身的燈片。
   - 方向燈：前面放在霧燈（白色、較低處）上，後面放在燈條兩端。
   - 燈要比車身表面高一點：先浮起 3 mm，再用 `clear_of` 逐步外推，直到完全不碰車身為止（曲面在兩個取樣點之間會鼓起來）。
   - 燈條尾燈加上自訂屬性 `bar`（匯出要開 `export_extras`），遊戲讀到就不放光暈。
8. **玻璃**（`split_glass`）：
   - 只認貼圖的「玻璃灰」：亮度 0.13～0.25、幾乎沒彩度。**條紋的黑比玻璃更黑（約 0.11）**，絕對不能用「黑色」判斷玻璃，否則會把條紋抓進來。
   - 從面積最大的候選面開始往外長，只接受法線跟它相差 12° 以內的鄰面。這樣車頂、引擎蓋、行李箱上被條紋邊緣弄成灰色的面，就不會黏進窗戶。
   - 驗證方法：把玻璃材質換成藍色，從前、後、側面渲染。
   - 車頂是黑色車身時（超跑），車頂的黑會落在玻璃灰的範圍裡，車頂整片變成玻璃。設 `roof_above`：這個高度以上朝上的面不當玻璃，而且整片換成車頂色（Tripo 還在超跑車頂的凹槽塗了一塊紅色）。
9. **塗裝**（`LIVERIES`、`livery_textures`）：每款塗裝一張完整貼圖。
   - 車漆像素（含它跟黑色之間的過渡）換成該款漆色，純色、不帶 Tripo 的假光影。
   - 朝上的面（引擎蓋、車頂、行李箱、鴨尾翹）上的黑色是條紋，換成條紋色；純色款就換成漆色。
   - 其他部位（水箱罩、燈座、輪拱內側）保留原貼圖。
   - 存成 JPEG，每張約 100～200 KB；PNG 壓不小，因為保留的部位有顆粒。檔案放在 `public/models/<car>/`，另外輸出 `liveries.json`。
10. **著色**：
    - `shade_smooth_by_angle(30°)`，再套 `WEIGHTED_NORMAL`（依面積加權）。不加權的話，生成的細長三角形會把法線拉歪，條紋上出現 X 形亮紋。
    - 每扇窗共用一個法線（`flat_windows`），否則鏡射的左右兩半在中線會有一道亮線。
11. **輪子**（`wheels.py`）：不用生成的輪子，因為遊戲要能轉動。輪胎和輪框分開做：
   - **輪胎**用真實規格產生（`Car.tyre`，例如 `"305/25 R20"`：胎寬 305 mm、胎壁高 25 %、20 吋），外徑就是遊戲用的輪胎半徑（`CarParams.wheelRadius` 要跟它一致）。輪胎外側面對齊原本生成輪胎的外側（`wheel_face`）。
   - **輪框**是模型：`tools/models/rims/<名稱>.blend`，可以直接在 Blender 打開修改。檔案裡只有一根輻條份的輪框（`slice`：外緣和輪圈的表面、`spoke`：輻條），程式依輻條數複製轉一圈；`hub`（輪轂、螺帽）和 `brake`（煞車碟）只用一次。模型的規則寫在 `wheels.py` 開頭。現有的 `thin-10`（超跑：細 10 輻、全黑）和 `bold-5`（肌肉車：粗 5 輻、拋光亮邊）是 `tools/models/rims/make_rims.py` 建的；新輪框就在那裡加一段，或直接在 Blender 照規則建。
   - **一圈固定 40 段**，所以輻條數只能是 4、5、8、10、20。輪框兩側胎唇的頂點必須每 9° 一個，跟輪胎的頂點重合，合併後整顆輪子沒有縫（程式會檢查，對不上就報錯）。
   - 輪框依輪胎的胎唇半徑和寬度縮放，同一個輪框可以配不同吋數。
   - **卡鉗**（`Car.caliper` 顏色）：有煞車碟的輪框才做，獨立物件 `caliper`。遊戲裡掛在轉向那層，跟著轉向但不跟著滾動；左側鏡射，兩邊都在車軸後方。
   - 面數：一顆要在 1,000 個三角形以內（現在 880～920，卡鉗另外 52）。輪胎和輪框必須保持 40 段，所以靠減少輪廓圈數：輪胎朝車身那側只留一段，輪框只留亮邊兩段和內側一段。輻條和輪轂直接疊上去，不用布林運算切合（切合會多出很多三角形）：插進輪框和輪轂裡的部分看不到，埋住的兩端也不封口。所以檢查會報輪子有穿插面和破邊，這是正常的。
   - 遊戲裡沒有環境反射，全金屬材質只剩燈光的亮點，看起來是黑的。要「亮的金屬」（煞車碟）就用亮色、金屬度 0.6 左右。
11-0. **輪拱內側**（`wheel_wells`）：補輪胎洞長出來的面帶著旁邊的車漆色，透過輪子看得到。輪拱裡朝向輪軸的面、輪胎外圍那圈朝外的平面，都改成獨立的深黑材質 `wheel_well`（不受塗裝影響）。
   - 生成的輪拱上方是空的，會直接看到車殼的背面。遊戲裡車漆只畫正面，背面另外用深黑色畫（`models.ts` 的 `SHELL_INSIDE`），所以從任何縫隙看進車殼都是黑的。
   - 試過在輪拱裡加內襯，但車殼裡殘留很多零碎的面，量不準內襯能多大，做大了就會從葉子板穿出來，所以放棄。
11-1. **碰撞外形**：**手寫座標**，放在 `src/vehicles/cars/<car>Collider.ts`，每個點都有註解寫它是哪裡（例如「左、車頭、底部」）。要調就直接改數字，每台車各自獨立。模型很少改，用參數去量反而難調，改一台還會牽動其他台，所以不用程式量。
   - 兩塊凸多面體。車身：車底到引擎蓋（和後車箱或尾翼），車頭到車尾。車艙：擋風玻璃底部、車頂、後窗底部。
   - 車身底部只在前後輪之間貼近底盤，往車頭、車尾要往上收（接近角、離去角）。底部一路平到車頭的話，重煞點頭兩三度就會插進路面，物理引擎把它推出來時，力臂在車頭，會把整台車掀起甚至彈飛。
   - 從上往下看，車頭、車尾的四個角要順著車身收進去；方角會凸出車身外，擦撞時容易勾到。
   - 引擎蓋往車頭降很多的車（超跑、改裝車），頂部也要順著引擎蓋斜降，不然車頭上方會空很大一塊。
   - 新車還沒有碰撞檔時，建模腳本會先寫一個包住整台車的方盒，從那裡開始調。
   - 建模腳本的預覽會讀碰撞檔，畫在車上（`collider-*.png`，包含俯視），改完重跑腳本就能看。
   - 接到 `CarSpec.collider`。碰撞體不帶質量，重量和重心仍由 `CarParams` 決定，所以不影響操控。
12. **檢查**（腳本會印出來）：穿插面、破邊、燈具和車身有沒有相碰、車身尺寸、三角形數。

## 4-1. 路人車（轎車、貨車、貨櫃車頭、拖車）

轎車、貨車、貨櫃車頭跟跑車同一套腳本（`sedan.py`、`truck.py`、`cab.py`）。**貨櫃拖車例外**：Tripo 兩版都把 12.5 m 長的拖車壓扁（長寬比只剩 3 左右，實際約 5），還破洞、貨櫃頂變斜屋頂。貨櫃本來就是方盒，所以 `trailer.py` 直接用方塊在 Blender 裡建（波浪側板、後門鎖桿、底盤、支撐腳、三軸），貨櫃顏色由遊戲直接上色（不用塗裝貼圖）。自己建面時要注意法線朝外，遊戲只畫正面，朝內的面會變成黑的。另外學到的：

- **概念圖三張都要是同一種 3D 渲染風格。** grok 有時把正側圖畫成平面插畫，車頭斜度也跟斜角圖不同，Tripo 就做出怪面（貨櫃車頭第一版駕駛室後面多一塊三角形）。提示詞要明寫「3D render, never a flat 2D illustration」。
- **Tripo 每次跑兩版比較**：三張圖一版、只給前後斜角一版。哪版好不一定（轎車是前後兩張那版好，車頭是三張那版好），並排渲染給使用者挑。
- **量輪胎和燈**：用正交正側、正面渲染加紅色地面線和中線（4.6 m 寬、2400 px），從圖上讀座標，比從網格猜準。
- **`width` 含後照鏡**（腳本用整台車的寬度縮放）。要讓車身寬度對，先量不含鏡子的車身寬，再換算成含鏡子的 `width`。
- **車窗**：轎車的擋風玻璃和後窗比跑車圓，`glass_bend` 放寬到 35°；窗上殘留的折線、細條用 `glass_fill` 吸進玻璃。車頂前緣的小台階、車頂中央的尖頂在 `mend` 裡壓平。車頭的側窗只畫在貼圖上（一大塊三角形跨過窗框），用 `glass_y` 讓只有擋風玻璃做成玻璃。
- **灰色、白色車漆**用亮度判斷（`paint_grey`）；深色車漆（車頭的深藍）設 `paint_fade`，不然換色時會被當成「漸暗到黑」而變暗。
- **貼圖共用像素**：Tripo 的貼圖會讓不同部位共用同一塊像素（貨車的駕駛室和貨箱共用白色，車頭的底盤和車漆共用深藍），用像素遮罩分不開，要按「面」分材質：
  - `plain`：指定區域裡的淺色面改成獨立的純色材質（貨車的貨箱固定白色）。
  - `trim`：面上完全沒有車漆的面改用原始貼圖（車漆色改成黑），所以底盤、鞍座、保險桿不會被染色。面上只要有一處車漆就算車漆面，避免半邊車窗半邊車漆的大面整片變黑。
- **三軸**：`tyres` 由前到後列出全部車軸，原點取第一軸和最後一軸的中點，中間軸的輪胎一樣會拆掉，預覽也會畫出來。後照鏡太小時在 `mend` 裡補一個盒子，貼圖取原本鏡子的黑色。
- 預覽相機依車長、車高自動拉遠（車子不受影響）。

## 5. 比對與驗收

- 預覽圖：前斜角、側面、後斜角跟概念圖並排比，另外看正面、俯視、正側（正交）。
- 修東西時做「修正前｜修正後」的並排圖。也可以逐像素比對渲染，確認只有該改的地方變了。
- 局部問題用特寫加線框：開 WIREFRAME modifier，搭配亮的打光。

## 6. 雜項地雷

- Blender 的 `render.filepath` 要給**絕對路徑**；相對路徑會寫到 `C:\` 根目錄。
- 匯出時 Blender 的 +Y（車頭）會變成 three.js 的 −Z。用 `import_scene.gltf` 讀回 GLB 時，車頭又回到 Blender 的 +Y。
- 用 Blender 讀 8-bit 圖時，`image.pixels` 拿到的是 sRGB 編碼的值。寫貼圖時直接用 0x 色碼除以 255，不要先轉線性。
- `carkit.py` 會 `import wheels`，所以會產生 `tools/models/__pycache__/`（已加進 `.gitignore`）。
- `bpy.data.libraries.load` 會把你給 `dst.objects` 的那個 list **原地換成物件**，之後要用名稱就先另外複製一份。

## 7. 新車清單

1. grok 概念圖三張 → `docs/art/<car>/`
2. `tripo.py multiview` → 挑結果 → `tools/models/src/<car>-tripo.glb`
3. 照 `supercar.py` 寫 `<car>.py`：量 `tyres`（生成的輪胎）、`src_ground`，填 `width`、`liveries`；燈具和局部修補依這台車的貼圖寫。車頂是黑色的話設 `roof_above`。
4. **輪子**（每台車都要）：
   - 輪胎規格 `tyre`：挑外徑接近生成輪胎的真實規格（腳本會印出兩者的半徑對照），寬度配車的個性。
   - 輪框 `rim`：照概念圖的樣式，沒有合適的就在 `make_rims.py` 加一款（輻條數 4、5、8、10、20），先單獨渲染輪子給使用者看過再上車。
   - **一定要有煞車碟和卡鉗**：煞車碟亮銀色（`make_rims.py` 的 `DISC`），卡鉗顏色寫在 `caliper`（超跑黃、改裝車紅、肌肉車黑）。輪框後面不要做整片擋住的凹盤，否則看不到煞車。
   - 一顆輪子 1,000 個三角形以內（腳本會印出來）。
   - `wheel_face`：輪胎外側面的位置，通常是生成輪胎的外側（`tyres` 的最後一個值附近）。
5. 跑腳本 → 看預覽（含輪拱：透過輪子不該看到車漆色）→ 修 → commit（`tools/models/`、`public/models/<car>.glb`、`public/models/<car>/`、碰撞檔）
6. 遊戲端：`src/vehicles/carModels.ts` 的 `FILES` 加一行；`CarSpec` 填模型的尺寸（`width`、`length`、`wheelbase`＝前後輪距離、`wheelRadius`＝輪胎規格的半徑）和 `collider`。車身背面變深黑、卡鉗掛在轉向那層，都是自動的。再依 `docs/ai-car-tuning.md` 調物理、訓練 AI。
7. 在遊戲車庫截圖確認（夜景很暗，看細節時暫時補一盞燈）。
